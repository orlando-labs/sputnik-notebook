# Notebook: зависимости, запуск и настройки

Исправления относятся к macOS-клиенту, web-клиенту и общему notebook core.
Registry и его правила назначения publisher не менялись.

1. **Dependencies.** В macOS добавлены подписанная кнопка в панели книги и
   команда меню Notebook. Боковая панель открывает тот же диалог. В web прямой
   вход уже существовал.
2. **Короткие имена.** Основной текст списка содержит короткое имя пакета;
   каноническая идентичность сохранена для проверки, удаления и подробностей.
3. **Общая установка.** Core устанавливает пакет в общее хранилище SDK. Книги
   получают отдельные ссылки на точную версию/сборку. Повторное подключение
   сверяет metadata registry и фактические SHA-256, identity и variant архива,
   затем использует готовую инсталляцию без скачивания. Изменения общего
   хранилища сериализованы файловой блокировкой. Удаление из книги удаляет
   ссылку; остальные книги продолжают работать. Общий кэш сохраняется.
   Существующая отдельная копия переводится на ссылку при явной повторной
   установке той же зависимости.
4. **Разрешения.** Оба клиента объясняют обязательные согласия на native code,
   сборку и размер. Install заблокирован до их выдачи; смена сборки сбрасывает
   согласия. Разрешение установки отделено от разрешения исполнения. В macOS
   есть отдельное подтверждение Grant Native Execution для текущего листа
   (либо controller-листа доски): `ffi.call`, `ffi.load`, `fs.read`. Web открывает
   существующий редактор разрешённых оператором worker grants.
5. **Импорт.** Registry-короткое имя связывается с реальным корнем модулей
   установленного пакета, например `torch → slowpilot.torch`. Связь сохраняется
   у книги в `packages/imports.index`, действует для подмодулей и передаётся
   существующему механизму import aliases. Во время Run сетевого разрешения
   имён нет. Явные aliases в коде и собственные модули книги имеют приоритет.
   Установка по полному имени тоже получает короткий импорт, если registry
   подтверждает принадлежность короткого имени этому пакету.
6. **Диагностика.** Ошибка отсутствующего импорта содержит имя модуля и действие
   Open Dependencies, без внутренних серверных путей. macOS переводит также
   старый формат ошибки remote core. Web сохраняет безопасную предметную
   причину вместо одной общей ошибки окружения.
7. **Run.** Кнопки ячейки, верхней панели и меню macOS используют общую проверку
   подключения, синхронизации, pending-команды и состояния исполнения. Web
   сохраняет существующую общую проверку `canRun`. Процесс worker по-прежнему
   может создаваться лениво при первом Run.
8. **Имя листа.** В macOS лист переименовывается через заголовок с карандашом
   или контекстное меню. Сохраняется только display title; stable ID, связи
   досок и черновики ячеек остаются прежними. Пустые имена и имена длиннее
   200 символов отклоняются. В web остаётся редактируемый заголовок с подсказкой.
9. **Servers.** Конфигурация серверов перенесена в Settings → Servers.
   Иконка рядом с выбирашкой открывает эту вкладку; отдельной кнопки Servers
   в книге больше нет. Save Server сохраняет профиль, не переключая открытую
   книгу на другой сервер.

## Проверки

Итоговые результаты и хэши сборки записываются в
`docs/evidence/2026-10-31/notebook-nine-fixes/validation.json`.

Регрессии покрывают два независимых notebook references, отсутствие второго
скачивания, короткий и канонический ввод имени, удаление одной ссылки,
неверный архив под правильным cached index, приоритет собственного модуля,
переименование без смены ID и раскрытия серверных путей. Браузерные проверки
дополнительно проверяют обязательные согласия и переход к grants.
