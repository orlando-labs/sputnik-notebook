# Ревью оставшегося scope компонентов и аудио

Дата: **20 октября 2026 года**. Статус: **продуктовое предложение перед P2**, не описание реализованного API. Основание — текущие исходники, инженерные контракты и [исходный roadmap](notebook-component-palette-roadmap.md). Согласованная модель: **AudioTrack — данные; AudioPlayer.for(track) — представление; notebook.show(player) — публикация**. Первая версия использует только системные возможности, принимает файл, бинарную строку полного файла с явным форматом либо PCM с заданными параметрами. **Добавление аудиоданных и streaming входят в базовый контракт**, по аналогии с Live Chart. Исторический аудит ниже описывает состояние до реализации; текущие этапы — в [плане реализации](notebook-p2-implementation.md), рабочий API — в [инженерном описании аудио](../engineering/notebook-audio.md).

## 1. Что изменилось после исходного плана

- До начала P2 в `NotebookComponentTool.all` было **24 компонента**: Layout — 2, Controls — 7, Display — 14, Services — 1. Stopwatch уже реализован и не должен снова попадать в backlog.
- P00/P0/P1 закрыли основной набор параметров, результатов и управления. **Parameter Presets остаются выполненной частью P1**.
- `DataTableView` из `notebook.ui` уже передаётся в `notebook.show(view, ...)`: публикация представления не меняет обычный результат ячейки. Для аудио сохраняется публикация представления, но аудиоданные выделены в самостоятельный `AudioTrack`, а плеер — в `AudioPlayer.for(track)`.
- Есть pre/post-компоненты ячеек: Input, Parameter Form, Live Chart, Metric, Image, Data Table. Это шесть допустимых видов, а не вся палитра доски. Для нового аудиовывода нужны лист, компоненты ячейки и доска в одном этапе.
- Remote core и GUI уже выполняют код, восстанавливают Run/epoch и передают presentations. Поддержаны локальные параметры ячеек и их Apply/Watch. Project inputs, Action/Periodic Work и передача произвольных файлов результата ещё не дают полной эквивалентности локальному режиму.
- **Аудиосемейства нет**: нет компонента, публичного аудиопредставления, транспорта аудиоданных, проигрывателя и записи. Символ `waveform.path` у Progress — только иконка.

Из scope по решению пользователя исключены Audio Compare/Collection, Audio Annotator/Transcript и Spectrogram.

Следующий этап должен закрывать законченные пользовательские сценарии. Число новых плиток само по себе не является целью.

## 5. AudioTrack, AudioPlayer и живой канал

Следующие примеры — **целевой API, сейчас не исполняется**. `AudioTrack` относится к самостоятельному аудиопакету (целевой импорт `audio`), `AudioPlayer` — к `notebook.ui`. Создание аудио, конверсия, экспорт и доступ к PCM для FFT не требуют создания или показа плеера. Конкретный DSP/FFT-пакет остаётся независимым от notebook UI.

Сохраняются **обе формы публикации**: простой `notebook.player(track, ...)` и явный `notebook.show(AudioPlayer.for(track, ...), ...)`. Короткая форма создаёт то же представление и публикует его через общий display path; она не включает звук автоматически и не является lookup по hard ID.

```sputnik
from audio import AudioTrack
from notebook.ui import AudioPlayer

# Файл: формат берётся из расширения; его можно переопределить format: "mp3".
track = AudioTrack.from_file("speech.mp3")
# Простая форма; импорт AudioPlayer для неё не требуется.
notebook.player(track)

# Явная форма с настройками представления и публикации.
player = AudioPlayer.for(track, position: 12.5, volume: 0.8)
notebook.show(player, id: "speech", caption: "Синтезированная речь", live: false)

# binary_contents — Str с точными bytes полного файла, включая заголовки.
# Для содержимого в памяти format обязателен, в виде расширения файла.
memory_track = AudioTrack.from_data(binary_contents, format: "wav")
notebook.show(AudioPlayer.for(memory_track), caption: "Аудиофайл из памяти")

# Raw PCM без заголовка: signed Int16 little endian, stereo L/R.
raw = AudioTrack.from_pcm(pcm_contents,
  sample_format: :s16le, sample_rate: 48000, channels: 2,
  layout: :stereo, interleaved: true)
notebook.show(AudioPlayer.for(raw), caption: "PCM из вычисления")

# Экспорт — операция аудиоданных, независимо от плеера и ноутбука.
fs.write_bytes("processed.wav", raw.to_wav(sample_format: :s16le))

# Последнее выражение остаётся обычным результатом ячейки.
42
```

### Три источника первой версии

| Factory | Что передаёт пользователь | Правила |
| --- | --- | --- |
| `AudioTrack.from_file(path, format: null)` | Путь к локальному для исполняющего код worker файлу. | Формат берётся из расширения, явный `format` его переопределяет. Если расширения нет, `format` обязателен. Трек захватывает bytes с обычными разрешениями и ограничениями памяти; последующая замена файла его не меняет. Путь не передаётся клиенту для открытия. |
| `AudioTrack.from_data(binary_string, format:)` | Бинарная `Str`, содержащая **полный аудиофайл**; также принимаются Bytes / ByteSlice / ByteBuffer. | `format` обязателен и задаётся расширением: `"mp3"`, `"wav"`, `"m4a"` и т. п. Это подсказка системному декодеру и проверяемое ожидание, а не указание представления PCM. |
| `AudioTrack.from_pcm(pcm_data, sample_format:, sample_rate:, channels: null, layout: null, interleaved: true)` | Raw PCM без заголовка — бинарная Str либо byte container. | Обязательны sample format/rate и channels либо однозначный channel layout. Если заданы оба, они должны согласоваться. `layout: :mono/:stereo` задаёт каналы/их порядок; `interleaved` отдельно задаёт размещение samples в памяти. Для planar — последовательные плоскости каналов одинаковой длины. |

**WAV — контейнер, PCM — представление samples.** `format: "wav"` означает полный RIFF/WAVE, с заголовками и chunks. Содержимое `fmt` определяет codec/sample representation в `data`; расширение `.wav` этого не гарантирует. См. [RIFF](https://learn.microsoft.com/en-us/windows/win32/xaudio2/resource-interchange-file-format--riff-) и [WAVEFORMATEX](https://learn.microsoft.com/en-us/windows/win32/api/mmreg/ns-mmreg-waveformatex). `format: "mp3"` аналогично означает содержимое MP3-файла. Не нужно угадывать по Str, является ли она путём или бинарным payload: методы различаются явно.

- `format` — непустая Str с одним расширением; регистр и начальная точка нормализуются (`".MP3"` → `"mp3"`). Это не MIME type и не имя кодека. По явному формату и содержимому файл проверяет системный backend; несовместимость или отсутствие декодера дают понятную ошибку, без неявного внешнего fallback.
- **Бинарная строка читается как точная последовательность bytes и длина в bytes.** NUL не завершает payload; нет UTF-8 decode/re-encode, нормализации Unicode, Base64 или текстового JSON transport. Вызов `fs.read_text` не является обязательным способом получить содержимое; byte containers равноправны Str. В snapshot/bridge payload хранится в бинарном виде.
- Поддержка encoded-форматов определяется системными возможностями клиента, а не искусственно ограничивается WAV. Для первой версии проверяются MP3 и RIFF/WAVE; M4A/AAC, AIFF, CAF и другие форматы добавляются в объявленный список после проверки. Наличие расширения в API не обещает соответствующий codec на любой версии OS.
- Базовые raw sample formats — `:s16le` (signed Int16 little endian) и `:f32le` (IEEE Float32 little endian); остальные добавляются как явно объявленные системные/adapter capabilities. Проверять положительную частоту, channels/layout, размер samples и целое число audio frames. Один audio frame содержит по одному sample каждого канала. Для f32le отклонять NaN/Inf; значения вне номинального диапазона не нормализовать и не обрезать молча. Если выбранный playback/export путь не принимает диапазон, возвращать явную ошибку.
- При `channels: 1/2` без layout используются mono/stereo. Однозначный layout позволяет вывести число каналов; неизвестное многоканальное расположение без явной схемы не угадывается. Порядок каналов и planar/interleaved — разные свойства. Спецификация не обещает многоканальный downmix до поддержки соответствующей схемы.
- Конверсия PCM к формату устройства может понадобиться для playback, но не переписывает исходные данные/экспорт. Удобный `from_samples` можно добавить позже поверх raw PCM; он не является четвёртым обязательным входом этого этапа.
- `AudioTrack` хранит аудиоданные и их параметры. Фабрики готового клипа создают immutable данные; преобразования возвращают новый трек. `to_pcm(...)` — получение PCM-трека, доступ к его samples позволяет передать данные отдельному FFT/DSP API. Декодирование/конверсия зависят от возможностей среды, но не от наличия плеера или GUI. Метод `to_wav(...)` возвращает bytes полного RIFF/WAVE.
- `AudioPlayer.for(track, position: 0.0, volume: 1.0, looped: false, autoplay: false, show_waveform: true)` описывает представление. `position` — начальная позиция в секундах, `volume` — 0..1. Отрицательная/NaN/Inf позиция и недопустимая громкость отклоняются; позиция после конца готового трека даёт ошибку, а не скрытый clamp. Для открытого потока позиция должна принадлежать retained диапазону. Создание объекта не открывает OS device; `show` публикует его, системным playback управляет клиент.
- `notebook.player(track, position: ..., volume: ..., looped: ..., autoplay: ..., show_waveform: ..., id: ..., caption: ..., order: ..., live: ..., throttle_ms: ...)` передаёт настройки представления в `AudioPlayer.for`, а настройки публикации — в `notebook.show`. Пропущенные параметры сохраняют их defaults. Валидация, результат вызова, ошибки, ID, streaming и lifecycle совпадают с явной формой; это удобная запись одного пути, не отдельный audio channel API.
- Публикация готового клипа копирует immutable snapshot: `encoded_file` (bytes + объявленный file format; выявленные container/codec — metadata decoder) либо `pcm` (data + sample_format/rate/channels/layout/interleaving). Не требуется упаковывать PCM в WAV. Позднее изменение строки/буфера/файла не меняет опубликованный клип. У потока передаются immutable chunks с фиксированными параметрами, а не каждый раз целый трек.
- Playhead/выделение относятся к player instance, не мутируют AudioTrack и не меняют выборку для FFT. Один трек может иметь несколько плееров с разными позициями/настройками. Экспорт данных получает диапазон явно: `track.to_wav(start_frame: ..., end_frame: ..., sample_format: :s16le)`. Интервал `[start_frame, end_frame)`, единица — audio frame.

### Streaming по тому же пути, что Live Chart

```sputnik
# Открытый AudioTrack с фиксированным PCM-форматом и ограниченным окном.
stream = AudioTrack.stream(sample_format: :f32le, sample_rate: 24000,
  channels: 1, buffer_seconds: 10)
notebook.show(AudioPlayer.for(stream), id: "speech-live")
# Альтернативная запись того же вызова (не второй вызов публикации):
# notebook.player(stream, id: "speech-live")

# По мере появления очередной порции данных, в пределах активного Run:
stream.append(pcm_chunk)
# ... следующие chunks ...
stream.finish()
```

`AudioTrack.stream(...)` — дополняемый источник того же аудиосемейства. Короткая и явная формы публикации одинаково подписываются на append/finish; повторная публикация каждого chunk не нужна. Готовый трек и stream имеют общую модель формата; только открытый stream допускает append. Операции над готовым immutable клипом не превращаются в изменение всех его плееров. Конкретное имя фабрики — предложение, согласованное требование — возможность добавлять данные до конца исполнения.

- `show(AudioPlayer.for(stream), id: ...)` связывает представление с живым источником текущей ячейки. `append` обновляет данные и все подписанные views; повторный `show` для каждого chunk не требуется. Без notebook тот же stream может служить источником для обработки аудиоданных.
- **Первый streaming-профиль — PCM.** Параметры задаются один раз при открытии. Chunk содержит целое число frames с теми же sample format/rate/channels/layout; другой формат требует явной конверсии или нового stream. Для planar chunk содержит одинаковое число frames каждого канала. Произвольные фрагменты MP3/WAV нельзя подавать как PCM или конкатенировать как независимые файлы.
- Для транспорта нужны отдельные события `begin`, `append`, `finish`, `reset` и состояния `interrupted/error`. Каждый append несёт run/generation, source/channel, sequence, начальный frame offset и immutable bytes. Это дельты как у Live Chart, с проверкой непрерывности frames; idempotent merge не проигрывает повторно уже полученные chunks.
- Audio callback и доставка данных не зависят от частоты отрисовки waveform. Coalescing объединяет соседние chunks без потери samples; пропуск промежуточных обновлений допустим для картинки waveform, но не для звучащего потока. `throttle_ms` представления не отбрасывает аудиоданные. Временная шкала определяется frame count / sample rate, а не временем прихода сетевого пакета.
- Источник хранит bounded retained window, клиент — отдельную bounded очередь playback. Предлагаемый `buffer_seconds: 10` ограничивает историю, а не всю длительность потока. Старые frames выводятся из retained окна с явным обновлением его начала; seek/loop доступны только в сохранившемся диапазоне. Бесконечное накопление bytes исключено.
- Непроигранные chunks не отбрасываются молча. При заполнении транспортной/playback очереди append получает backpressure с кооперативным ожиданием и ограниченным таймаутом; Pause, отсутствие клиента или потеря связи не могут блокировать Run бессрочно. По таймауту — явная ошибка. Режим live-monitor с пропуском старого аудио, если понадобится, включается отдельно и показывает gaps/drop counters.
- При underrun системный sink выдаёт тишину и состояние `buffering`; будущие frames не заменяются и их порядок не меняется. Поступление данных продолжает воспроизведение, только если пользователь уже включил Play. Default `autoplay: false` сохраняется; явное `autoplay: true` — настройка данного плеера.
- `finish()` закрывает запись, фиксирует последний frame count и даёт проиграть очередь до конца. Append после finish — ошибка. Ошибка/Stop помечают поток interrupted и останавливают playback; полученные retained frames остаются явно частичным результатом. Неявное успешное завершение ячейки закрывает ещё открытые streams после drain владельца, включая принятые structured tasks. Старые producers не могут дописать в следующую generation.
- Snapshot для reconnect содержит формат, retained frame range, sequence и terminal state. Reattach восстанавливает окно и состояние, не перезапускает Run, не повторяет playback-команды и не включает звук автоматически. Потерянные frames вне retention нельзя выдать за полную запись.
- Экспорт потока фиксирует retained диапазон и явно помечает частичный output. Полная запись требует отдельного archive-to-file sink с дисковыми лимитами; она не следует автоматически из наличия плеера.

### Управление компонентом по hard ID

`AudioPlayer.for(...)` — описание представления, а обращение к размещённому компоненту возвращает runtime handle. Предлагаемое написание lookup:

```sputnik
# hard ID компонента из инспектора; board задаёт область уникальности.
player = notebook.component("preview-player", board: "audio-board")
player.seek(12.5)  # секунды
player.play()
player.pause()

# Если компонент уже связан с открытым PCM stream:
player.append(pcm_chunk)
player.finish()
```

- В текущем manifest component IDs уникальны внутри доски, включая nested panels; у cell components область — ячейка. Поэтому lookup включает `board`, либо `cell` (с опциональным `sheet`, если нужен чужой лист), а без scope использует текущую ячейку. Не выполнять поиск «первого похожего» компонента по всему проекту. Расширение имени generic lookup на другие виды — отдельная задача; здесь достаточно player handle.
- **Hard ID компонента, `show(..., id: ...)` и identity AudioTrack — разные вещи.** Первый адресует размещённый UI instance, второй — output channel владельца-ячейки, третий — источник данных. Источник канала выбирается в инспекторе; hard ID копируется из инспектора и не заменяет обычную пользовательскую подпись. Дублирование компонента создаёт новый hard ID.
- Handle поддерживает `play/pause/stop/seek`, изменение громкости; append/finish доступны только при привязке к открытому stream. Они маршрутизируются к тому же источнику и не создают скрытую вторую копию трека. И append у stream, и append у handle используют один упорядоченный producer-контракт. Иные ячейки не получают право записи в чужой живой источник только из знания ID; нужен объявленный источник/владелец.
- Playback-команды выполняет клиент, а не worker. По bridge передаются bounded команды с generation/sequence и подтверждением; дубликат не повторяет Play/seek. Отсутствующий/удалённый компонент, неверный вид, закрытая generation или offline дают явный результат ошибки. Команды не ждут безгранично, не записываются в defaults и не replay-ятся при reconnect.
- Ручные действия и код идут через один player controller. UI-настройка/Play/Pause не исполняют notebook code. Handle не является OS pointer и не обещает синхронное чтение живого состояния Mac из Linux worker.

### Публикация и жизненный цикл

- Использовать существующие `caption`, `id`, `order`, `live`, `throttle_ms`. Повтор `show` с тем же `id` заменяет представление в пределах владельца-ячейки; append дополняет его stream. Публичное имя канала не объединяет outputs разных ячеек.
- При заданном `id` сохранить общую семантику `show`, включая live по умолчанию. `live: false` подходит готовому треку. Публикация открытого stream требует `id` и `live: true` (явно либо по default с ID); `live: false` для него отклоняется. Replacement snapshot и append — разные события одного display lifecycle.
- Успешный Run фиксирует результат. Ошибка/Stop сохраняют прежний committed клип с его актуальностью; новый незавершённый вывод может оставаться только явно помеченным preview/телеметрией. Старый результат не подменяется частичным «успехом».
- Replacement/new generation останавливает прежнее воспроизведение и применяет position/настройки нового AudioPlayer; обычный append не сбрасывает playhead. Reopen/reconnect ничего не проигрывает автоматически. Удаление владельца останавливает playback и освобождает ресурсы.
- Новые локальные outputs по умолчанию остаются runtime state, как прочие displays. **Save original / Save to project** — явное сохранение. Для remote snapshots используется существующее хранение presentation; доступность старых bytes зависит от retention, а не от сохранённого заголовка компонента.

### Меню объекта

Одно меню `⋯` на листе и доске:

1. **Save original…** — точные исходные bytes полного encoded-файла, весь клип. Для `from_pcm` готового исходного файла нет: вместо этого доступны Export WAV и явно названный Export raw PCM с descriptor metadata.
2. **Export WAV…** — весь клип или выбранный диапазон; выбор PCM16/Float32; сохранение частоты и каналов. Конвертация и экспорт диапазона не называются «оригиналом».
3. **Copy metadata** — длительность, sample rate, channels, frame count, encoding и provenance.
4. **Copy metadata** также сообщает retained frame range потока; экспорт разметки/спектрограммы не входит в scope.

Меню должно явно показывать область экспорта и ограничения retained данных. Нельзя сохранять waveform preview под видом полного аудио. Ошибка экспорта видна рядом с объектом.

## 6. Общие правила листа и доски

- **Лист:** `show(player)` автоматически добавляет audio output; явный post-cell Audio Player выбирает канал и заменяет его автоматическое отображение без дубликата. Остальные каналы остаются видимыми. Для output-компонента разрешены те же pre/post-позиции, что у Image/Data Table, с понятным ожиданием до первого Run.
- **Доска в Design:** выбираются источник, публичный канал, размеры, видимость waveform/metadata, исходная громкость и доступность экспорта. Настройка/drag/resize не запускают код и playback. На плитке — название и совместимый preview/placeholder.
- **Show waveform — обязательная редактируемая опция плеера в инспекторе Board Designer.** Boolean `show_waveform`, default `true`; сохраняется с конфигурацией компонента через Save Board и участвует в Undo/Redo/дублировании. Явное значение доски имеет приоритет над `AudioPlayer.for(..., show_waveform: ...)`; без override используется настройка опубликованного player. Новый Run/append не переписывает дизайнерский выбор.
- При выключенном Show waveform остаются transport controls, позиция/длительность и меню экспорта. Waveform скрыта целиком; её необязательное вычисление/перерисовка не требуется, если нет другого потребителя. Изменение опции обновляет preview в дизайнере и итоговый layout (auto height либо текущая фиксированная строка), не вызывает Run, не меняет AudioTrack, playhead и очередь streaming. Опция работает одинаково для файла, бинарного содержимого, готового PCM и открытого потока.
- **Доска в Run:** тот же renderer, включая меню, stale/empty/error и playback. Компонент участвует в общей сетке и высоте строки. Это не floating control поверх layout.
- **Input в Design:** редактируются источник и режимы импорта/записи, но микрофон не открывается. В Run выбирается файл/записывается draft; Accept/Apply принимает данные. Run вычисления остаётся отдельным действием, кроме уже настроенных зависимостей Watch после Apply.
- Если один player показан на листе и доске, playback привязан к identity представления: переключение UI не создаёт второе одновременное воспроизведение. Разные `AudioPlayer.for` над одним AudioTrack имеют отдельные позиции/настройки. По умолчанию в документе активен один playback source; Play другого останавливает прежний.
- Воспроизведение и запись происходят **на клиенте**, независимо от расположения worker. Потеря соединения не обрывает воспроизведение полностью загруженного клипа; Apply нового input при offline недоступен. Перезапуск server worker не перезапускает микрофон клиента.
- Использовать существующие категории и цвета: Audio Player — Display, Audio Input — Controls. Сохранить тёплую гамму, текстовые подписи, клавиатуру, доступные альтернативы drag для seek/границ. Не добавлять отдельный яркий цвет всем media-компонентам.
- Источник выбирать по имени листа/подписи ячейки и caption. Внутренние asset/cell/run IDs нужны хранению и связям; они не становятся основными подписями пользователя.

## 7. Audio Input, запись и чтение из кода

**Предлагаемый контракт P2-B:** импорт и Accept записи создают managed audio asset в проекте. Сохраняются immutable bytes, representation (`encoded_file`/`pcm`), явный file format и раздельные обнаруженные container/codec либо PCM sample format/rate/channels/layout/interleaving, frame count и версия. Recorder фиксирует take как полный RIFF/WAVE PCM16. Preview, новый take и границы обрезки сначала остаются draft. Accept атомарно принимает снимок; Cancel сохраняет прежний. До успешного сохранения bytes нельзя публиковать ссылку в manifest.

Входной клип не нужно кодировать как числовой/string project input или заменять его локальным абсолютным путём. Для managed media вводится отдельный capture-контракт, используя опыт readable Image. Целевой helper:

```sputnik
# Предложение P2-B, также пока не реализовано.
from notebook.ui import AudioPlayer, read_audio

track = read_audio("speech", scope: :cell)
if track != null:
  notebook.show(AudioPlayer.for(track), caption: "Принятый клип")
```

`scope: :cell` читает input исполняющейся ячейки, `scope: :project` — явно разрешённый общий input; scope обязателен. При отсутствии принятого клипа возвращается `null`, и код обязан его обработать. Reader возвращает **AudioTrack принятого снимка**, готовый для обработки/экспорта или `AudioPlayer.for`. Внутренний descriptor хранит representation, bytes, format/codec либо PCM metadata и asset version; он не становится отдельным публичным форматом вместо AudioTrack. Это принятый input, не опубликованный player и не его playhead. Read dependency участвует в общей invalidation-семантике. Снимок фиксируется при старте invocation; detached работа не читает последующие edits.

Для remote Apply сначала синхронизируются bytes/version, затем принимается input. Нужны объявленная capability и атомарный accepted snapshot; при неподдерживаемом core UI объясняет необходимость обновления. После Apply Watch следует обычным зависимостям, Manual ожидает явный Run; оба читают точный принятый снимок. Не подменять серверный input локальным выполнением.

Record доступен по явному нажатию пользователя и запросу доступа к микрофону. Предлагаемый предел take — **60 секунд или бюджет bytes, что наступит раньше**; предел показывается до старта. Запись останавливается в draft и ожидает Accept/Discard. Формат записи выбирается явно; стартовый preset — mono PCM16, 48 kHz, при поддержке устройством/adapter. Отказ в доступе, смена/отключение устройства и закрытие документа не публикуют частичный take как принятый input. Исходная запись до подтверждения импорта хранится временно; срок и очистка временных файлов входят в задачу Recorder.

## 8. Ограничения и реализация по слоям

- В текущем display collector есть лимиты **16 MiB на payload и 64 MiB / 64 panels на ячейку**. Готовый audio snapshot вместе с metadata должен укладываться в эти бюджеты. Для stream отдельно ограничить размер chunk и суммарные retained bytes/очереди в пределах того же memory budget; полная длительность не ограничивается размером одного display. Для примера, 60 секунд stereo PCM16 при 48 kHz — 11 520 000 bytes без заголовка, Float32 — вдвое больше и уже потребует streaming/archive вместо одного большого snapshot.
- Дополнительно ограничить decoded PCM: предложение — **32 MiB на клип**, mono/stereo, и **64 MiB общего decoded cache документа** с LRU-очисткой неактивных клипов. Декодировать по потребности, не все 64 outputs одновременно. Проверять размер/арифметику frame count до выделения буфера; повреждённый или неподдержанный WAV не должен попадать в player.
- Для waveform передавать/строить bounded min/max envelope: например, не более 2048 bucket pairs на канал для overview. Zoom использует ограниченный cache исходных данных. Миллионы samples не должны становиться SwiftUI elements или точками Live Chart.
- Для статического snapshot лимиты ограничивают размер клипа; длинный live stream работает через bounded окно и backpressure. Полная запись длинного потока требует archive sink, дисковых квот и retention. Ограниченное окно/невозможный seek видны в UI; сохранённый фрагмент не называется полной записью.
- Versioned transport передаёт только inert bytes и metadata, без VM handles и OS file/device handles. Проверки существуют и на стороне producer, и на UI boundary. Неподдержанный audio display получает понятный placeholder, а не декодируется как PNG.
- Container/codec I/O образуют переносимый слой, воспроизведение и запись — платформенный adapter клиента. DSP, ASR, TTS и загрузка моделей остаются явным пользовательским кодом/пакетами. Кодековая поддержка в UI и получение PCM в Linux worker проверяются отдельно.

### Системный backend первой версии

**Решение пользователя: только системные возможности, без FFmpeg и внешнего codec helper в первом этапе.** На macOS системный `AVAudioEngine` управляет playback, `AVAudioFile` читает поддержанные системой файлы в `AVAudioPCMBuffer`; PCM подаётся в engine без контейнера WAV. [Apple: AVAudioEngine](https://developer.apple.com/documentation/avfaudio/avaudioengine), [AVAudioFile](https://developer.apple.com/documentation/avfaudio/avaudiofile).

Граница слоёв:

1. `AudioTrack` владеет encoded/PCM данными или открытым источником. `AudioPlayer.for(track)` добавляет настройки представления, `show` публикует snapshot либо подписывает его на audio deltas. Файл открывает сторона исполнения с обычными разрешениями; содержимое и file format передаются клиенту. Decoder не обязателен на worker только ради публикации аудио.
2. macOS-клиент валидирует encoded-файл и декодирует его системным API; PCM передаёт системному playback controller с параметрами. Если выбранному системному API нужен URL, adapter создаёт временный файл с объявленным расширением из точных bytes. Это внутренняя деталь, с ограничениями размера, сроком жизни и очисткой после освобождения snapshot.
3. Формат устройства может требовать системного преобразования rate/sample representation/layout. Это playback conversion; исходный snapshot не меняется. Неизвестный layout, неподдержанный file format и повреждённые данные дают явную ошибку на объекте.
4. Linux worker может читать файл, получить бинарную строку или сформировать PCM, включая поток порций, и опубликовать их для воспроизведения на Mac. AudioTrack пригоден для обработки независимо от notebook: доступные преобразования зависят от backend среды. Если Linux не располагает decoder для конкретного encoded-формата, операция возвращает unsupported или используется явно подключённый пользователем пакет. Создание плеера не является условием и не скрывает отправку данных в Mac ради DSP.
5. Базовый `to_wav` над raw PCM реализуется переносимой упаковкой RIFF/WAVE, без внешнего codec. Экспорт encoded-клипа в WAV/выбранного диапазона в UI выполняется системным decoder/exporter. Объектный export encoded-файла там, где системного decoder нет, возвращает unsupported; Save original остаётся доступен по bytes.

Конкретный набор container/codec и точность seek проверяются на поддерживаемых версиях macOS. Первые acceptance fixtures — один и тот же MP3/WAV с диска и из бинарной строки, s16le/f32le PCM, mono/stereo, interleaved/planar; отдельно — поток chunks во время Run, без повторной публикации полного трека. Дополнительные расширения считаются поддержанными после реального decode/playback, а не по имени файла. Отсутствующий codec не вызывает автоматический запуск `ffmpeg` из PATH.

FFmpeg остаётся возможным будущим расширением только при новой потребности. Его сборка, поставка и матрица codecs **не входят в текущий scope**.

## 9. Рекомендуемый порядок и критерии готовности

| Порядок | Законченный результат | Критерий приёмки |
| --- | --- | --- |
| **1. P2-A: AudioTrack + Audio Player + streaming** | Независимые данные → `AudioPlayer.for(track, position: ...)` → `notebook.show`; управление компонентом по hard ID; PCM append во время Run → системный sink через bounded live channel. | MP3/WAV из файла/Str и PCM; конверсия/экспорт без UI; начальная позиция и команды по hard ID. Show waveform меняется в Board Designer, сохраняется после reopen и имеет приоритет над кодом; переключение не сбрасывает playback/stream. Несколько chunks звучат до конца Run, append не сбрасывает playhead; проверить sequence/повторы/gaps, buffering, backpressure/таймаут, Pause, finish, Stop, reset generation, reconnect без autoplay/replay, ограниченную память и честный экспорт retained диапазона. |
| **2. P2-A: Run History и Runtime Status** | История с сохранёнными provenance и outputs; актуальные сведения об окружении/соединении. | Старый запуск можно открыть после нового; pin/delete/retention определены; Apply старых параметров не запускает код; нет данных ресурса не выглядит нулевой нагрузкой. |
| **3. P2-B: assets и Audio Input / Recorder** | Переносимый импорт, запись в draft, accepted input snapshots, local/remote Run. | Проект переносится без исходного внешнего файла; Cancel не меняет input; микрофон открывается только Record; offline/permission/device errors понятны; Run читает точно принятые bytes. |
| **4. P2-B: selection, Compare, Image Annotator, live logs** | Связанные представления и управляемые редактируемые снимки; сравнение экспериментов. | Таблица выбирает нужный asset по стабильному ключу; применение диапазона атомарно; смена версии не переносит метки молча. Каждая возможность выпускается отдельной проверяемой задачей. |
| **5. P2-C** | Task Monitor, ресурсы, Date-time, Split View. | Для каждой функции есть реальный сценарий и необходимые данные/capability. Одна демодоска проверяет весь заявленный путь; отсутствие данных остаётся видимым. |

Для первого аудиопримера достаточно локально генерируемого короткого сигнала и пары original/processed; не требуются загрузка модели или внешние сервисы. Следующий пример — импорт/запись → явная обработка → исходный/обработанный клип → Metric/Data Table. Проверки должны подтверждать слышимый playback, а не только успешный decode/скриншот; отдельно нужны channel order, точность границ экспорта, corrupted/oversized input и Linux worker → macOS client.
